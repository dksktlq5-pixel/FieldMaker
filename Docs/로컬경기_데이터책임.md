# 로컬 1v1 경기 기반 데이터 책임

2026-11-06. 로컬 리슨 서버의 호스트가 서버 권한을 가진다. 클라이언트가 점수나 경기 단계를 직접 결정하지 않는다.

| 소유자 | 책임 | 복제/입력 |
|---|---|---|
| AFMGameMode | 접속 시 균형 팀 배정, 팀별 시작 위치 선택, 양 팀 존재 여부 판정 | 서버에만 존재 |
| AFMGameState | 단계·라운드 번호·양 팀 승점·서버 종료 시각·진영 교체 여부 | FFMMatchSnapshot 단위로 서버에서 복제 |
| AFMPlayerState | 팀과 외형, 향후 자금·전적·보유 수량 | 기존 팀/외형 복제 재사용 |
| AFMPlayerController | 로컬 입력, 기존 장비/공격 요청, HUD | 기존 서버 RPC 재사용 |
| AFMCharacter | 기존 이동·체력·무기·공격 처리·외형 표시 | 기존 복제와 피해 검사 재사용 |
| AFMCombatHUD | 실제 승점과 팀 인원 구분, 로컬 팀·단계·시간 표시 | GameState와 PlayerState를 읽어 표시 |

팀 배정은 InitNewPlayer에서 상위 클래스의 시작 지점 선택 전에 실행한다. 팀 스폰은 PlayerStartTag FM_Team0 / FM_Team1로 구분한다. 진영 교체 플래그는 스폰 방향 선택에만 사용하며 팀 번호를 변경하지 않는다.

새 맵 `/Game/Map/L_FMLocalMatchTest`의 GameMode Override는 `/Game/FieldMaker/Rules/BP_FMLocalMatchMode`다. 기존 FMGameMode를 상속하고 TeamMatch만 활성화한다. 기존 이동 테스트 맵과 메인 메뉴는 보존한다.

현재 범위는 WaitingForPlayers → Ready의 경기 시작 전 기반이다. Ready는 양 팀 접속을 뜻하며 칼전 시작을 의미하지 않는다. PhaseEndServerTime이 0이면 시간은 --로 표시한다. 서버 시각 기반 남은 시간 계산은 준비했지만 칼전·라운드 타이머 시작/전환은 다음 구현 범위다.

경기 종료/진영 교체/점수 지급/관전/인원 제한/중간 참가 정책은 아직 이 기반에 연결하지 않았다. 현재 테스트 맵은 기존 무기 검증을 허용하며 정식 단계별 공격 제한은 다음 전투/라운드 작업에서 연결한다.

무기·방어구 수치 DataTable/DataAsset과 전투/건설 컴포넌트 분리는 이번 작업에서 추가하지 않았다. 기존 시스템을 재사용하며 해당 기능 구현 시 책임을 확장한다.

## 2026-11-07 개발 테스트 상태 갱신

BP_FMLocalMatchMode에 CombatSandbox를 켰다. L_FMLocalMatchTest에서는 CombatTest(FIRE TEST)로 시작해 사격/ADS/피해를 검증할 수 있다. 정식 게임의 Ready/구매/구축/결과 상태는 공격을 차단한다. 이는 자동 칼전이나 라운드 흐름의 구현을 뜻하지 않는다.
